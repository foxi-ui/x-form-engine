# ADR-0001 设计器与 antd 5 升级路径

> 状态：已接受（Accepted）  
> 日期：2026-11-07  
> 关联：《Form Engine 企业级前端渲染引擎设计方案》第 13、19 节

## 1. 上下文

- 上游 Designable 无 2.x，最新为 `1.0.0-beta.45`（发布于 2022-02-28，此后无新版本），peer 依赖锁定 **React 16/17 + antd 4**。
- 为「先跑通架构」，当前基线按方案 1 锁定：**React 17.0.2 + antd 4.22.8 + @formily/* 2.3.7 + @designable/* 1.0.0-beta.45**（见 `verification/01-version-lock.md`）。
- 后续有升级 antd 5 的诉求。但 Designable 1.x 无法「升级」到 antd 5 / React 18，只能**整体替换**。

## 2. 决策

1. **设计器是临时资产**：antd 5 升级等价于重写设计器（自研核心或维护 fork）。Designable 1.x 仅作为当前阶段的可行性依赖与概念参考，不视为长期生产资产。
2. **引入 antd 无关的组件接口层**：PC 组件实现通过该接口访问 UI 原语，**禁止组件实现直接 `import antd`**。借自 `@formily/antd` 的组件单独登记「替换清单」，升级时逐项替换或自建。
3. **升级触发点**：运行时 M1 / M2 稳定后启动；**验收标准**：设计器自研 spike + antd 5 运行时 spike 均通过，方可进入升级实施。
4. **升级前约束**：评审门禁检查「组件内是否直接 import antd 专属 API」，违者不允许合并；替换清单随组件变更维护。

## 3. 后果

- **接受的代价**：当前全栈锁定 React 17 + antd 4，接受多年代际锁定，换取快速落地。
- **升级成本前置**：antd 5 升级时设计器需重写，工时须单独评估，不计入「换组件库」的轻量估算。
- **所见即所得**：设计器画布与运行时 Renderer 是两条渲染路径，WYSIWYG 靠「同一份组件实现 + 同一份 Schema 编译产物 + 一致性验收用例」保证，而非复用同一渲染入口。

## 4. 门禁与验收

- [ ] 组件实现层无直接 antd 依赖（静态检查/评审）。
- [ ] 「替换清单」列出所有借用的 `@formily/antd` 组件及其替换计划。
- [ ] antd 5 运行时 spike 通过（Formily 原生能力不回归）。
- [ ] 设计器自研 spike 通过（物料、Setter、Schema 回写可用）。
- [ ] 升级决策与范围写入版本变更记录。
